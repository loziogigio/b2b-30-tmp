# SEO URL Architecture — flat product slugs + dynamic category root (vcs-generated SEO)

**Date:** 2026-05-20
**Repos:** `vinc-commerce-suite` (vcs — generator/source of truth) · `vinc-b2b` (consumer)
**Status:** Approved for implementation (multi-agent)

---

## 1. Goal

Give the B2B storefront (`vinc-b2b`) an SEO-indexable, server-rendered URL scheme, with the
authoritative data generated by `vinc-commerce-suite`:

- **Product detail** at a flat slug: `/{lang}/{product-slug}` (e.g. `/it/250-pz-monoporzione-in-carta-59-ml-kraft-200-2050k`), SSR, with breadcrumb + JSON-LD. Still reachable by SKU (`/products?sku=`, `/products/{sku}`) as secondary access that canonical-points to the flat slug.
- **Category** at `/{lang}/{root}/{path…}` where `{root}` is a **backend-declared, per-tenant** segment (e.g. `prodotti`), defaulting to `categorie`. The existing SSR leaf grid (`CategorySeoProducts`) is reused unchanged.
- **Dynamic `sitemap.xml` and `robots.txt`** for vinc-b2b, **generated by vcs per-tenant** and consumed by vinc-b2b (mirroring the existing B2C sitemap pattern).

## 2. Current state (verified)

- vinc-b2b product detail: `src/app/[lang]/(default)/products/page.tsx` (`?sku=`) and `src/app/[lang]/(default)/products/[...slug]/page.tsx` (sku via path). Both resolve **by SKU only** via `fetchProductForSeo`/`serverFetchPimProducts` (PIM `/api/search/search` with `filters.sku`). No slug→product lookup exists.
- PIM product carries a `slug` (`get-pim-product.tsx:177` → `raw.slug || sku.toLowerCase()`); in vcs the model stores a **multilingual** `slug` (`src/lib/db/models/pim-product.ts:158`).
- Category route: `src/app/[lang]/categorie/[[...slug]]/page.tsx` → `findNodeByPath` over the PIM menu tree → `CategorySeoProducts` renders the SSR leaf grid (facets as `?filters-*` anchors, `?page=N` pagination, schema.org). Segment `categorie` is **hardcoded**.
- Flat single-segment route `src/app/[lang]/(default)/[slug]/page.tsx` → CMS page via `getCachedCmsPage`, else `notFound()`.
- vinc-b2b `src/app/sitemap.ts`: self-generates (home/search/categorie/collections + category paths + collection slugs + product `/{lang}/products/{sku}`). `src/app/robots.ts`: **static**.
- vcs already has the B2C analog: `src/lib/services/b2c-sitemap.service.ts` (+ `b2c-sitemap` model + public domain-aware API) emitting `/{locale}/{slug}` products and `/{locale}/{path}` categories for the B2C frontend. **This is the pattern to mirror for B2B.**

## 3. Decisions

- **D1 — Slug resolution via "search-by-slug".** The PIM search gains a `slug` filter (peer of `sku`). vcs's resolver endpoint is _search with a `slug` filter_; the filter is reusable by vinc-b2b's own search layer.
- **D2 — Category root is dynamic, per-tenant, backend-declared.** Default `categorie`; may be localized per locale. Provided by vcs.
- **D3 — Resolution by segment count (lower risk than one mega catch-all):**
  - **Multi-segment** `/{lang}/{root}/{a}/{b}…` → category. The existing `/categorie/[[...slug]]` route stays; for a non-`categorie` root, a middleware rewrite maps `/{lang}/{root}/…` → `/{lang}/categorie/…`.
  - **Single segment** `/{lang}/{slug}` → resolve in order: **CMS page → product (vcs resolve-product) → 404.** Extends the existing `[slug]` route.
- **D4 — Canonical = flat slug.** `/products?sku=` and `/products/{sku}` keep working but emit `<link rel=canonical>` to `/{lang}/{slug}` (when a slug exists).
- **D5 — vcs is authoritative for sitemap + robots.** vinc-b2b's `sitemap.ts`/`robots.ts` become thin consumers of vcs APIs (with a safe fallback to current behavior if vcs is unreachable).

## 4. URL scheme

| URL                                                | Renders                                           | Route file (vinc-b2b)                                                                 |
| -------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `/{lang}/{slug}` (1 seg)                           | CMS page → else product detail → else 404         | `[lang]/(default)/[slug]/page.tsx` (extended)                                         |
| `/{lang}/{root}/{path…}`                           | Category SSR leaf grid                            | `[lang]/categorie/[[...slug]]/page.tsx` (+ middleware rewrite when `root!=categorie`) |
| `/{lang}/products?sku=` , `/{lang}/products/{sku}` | Product detail (secondary; canonical → flat slug) | existing, add canonical                                                               |

## 5. API contract — vcs public, domain/tenant-aware endpoints

Tenant resolved from request host (same mechanism as `b2c/public/sitemap-data`). All under `/api/public/b2b/`.

### 5.1 `GET /api/public/b2b/resolve-product?slug={slug}&lang={lang}`

- Looks up a published `PIMProduct` whose `slug[lang]` (or any locale, fallback) === `slug`, scoped to tenant. Implemented via the **slug-filtered search** (D1).
- **200**: `{ sku, parentSku, name, slug, categoryAncestors: string[], found: true }`
- **404**: `{ found: false }`
- Cacheable (`revalidate` + tenant tag).

### 5.2 `GET /api/public/b2b/seo-config`

Per-tenant SEO/routing config consumed by vinc-b2b:

```json
{
  "categoryRoot": {
    "default": "categorie",
    "it": "prodotti",
    "en": "products"
  },
  "robots": {
    "noindex": false,
    "allow": ["/"],
    "disallow": [
      "/api/",
      "/account/",
      "/checkout/",
      "/complete-order/",
      "/*?preview=true"
    ],
    "sitemapUrl": "https://{host}/sitemap.xml"
  }
}
```

`categoryRoot.default` falls back to `categorie`. `noindex:true` ⇒ robots emits `Disallow: /`.

### 5.3 `GET /api/public/b2b/sitemap-data`

Per-tenant sitemap entries (mirrors `b2c-sitemap.service`):

```json
{
  "baseUrl": "https://{host}",
  "langs": ["it", "en"],
  "entries": [
    {
      "loc": "/{lang}/{slug}",
      "type": "product",
      "changefreq": "weekly",
      "priority": 0.6,
      "lastmod": "..."
    },
    {
      "loc": "/{lang}/{root}/{path}",
      "type": "category",
      "changefreq": "weekly",
      "priority": 0.7
    },
    { "loc": "/{lang}/{cms-slug}", "type": "page", "priority": 0.4 },
    { "loc": "/{lang}/search", "type": "static", "priority": 0.8 }
  ]
}
```

Products are emitted with their **flat slug** (per locale). Backed by direct Mongo access to `pimproducts` (slugs) + categories + CMS pages. Cached + tenant-tagged; revalidated on publish (reuse existing sitemap invalidation pub/sub).

## 6. vcs implementation plan

1. **Search `slug` filter (D1):** add `slug` to the PIM search filter handling (peer of `sku`) wherever the B2B search query is built server-side; ensure the PIM `/api/search/search` body forwards `filters.slug`. If the upstream PIM engine cannot filter by slug, fall back to a Mongo `pimproducts` query by `slug.{lang}` inside the resolver. Unit-test both paths.
2. **`resolve-product` route** (`src/app/api/public/b2b/resolve-product/route.ts`): tenant-from-host, slug lookup, shape per §5.1.
3. **`seo-config` route** (`src/app/api/public/b2b/seo-config/route.ts`): read tenant/storefront config; `categoryRoot` + `robots`. Add config fields to the relevant tenant/storefront model with safe defaults (`categorie`, `noindex:false`).
4. **B2B sitemap service + route**: `src/lib/services/b2b-sitemap.service.ts` (sibling of `b2c-sitemap.service.ts`) + `src/app/api/public/b2b/sitemap-data/route.ts`. Reuse collection patterns; emit product **slug** URLs, category paths (using `categoryRoot`), CMS pages, static routes.
5. **Tests:** resolver (found/not-found/tenant scope/locale fallback), sitemap builder (URL shapes per type, locale alternates), seo-config (defaults + noindex).

## 7. vinc-b2b implementation plan

1. **vcs client** (`src/lib/vcs/seo.ts`): typed fetchers for `resolve-product`, `seo-config`, `sitemap-data`, domain-aware, cached (`next: { revalidate, tags }`), each with a **safe fallback** (resolve→null; seo-config→`{categoryRoot:'categorie', robots: <current static>}`; sitemap→current local generation).
2. **Flat product at `[slug]` (D3 single-segment):** extend `[lang]/(default)/[slug]/page.tsx`: CMS lookup → else `resolve-product(slug,lang)` → if found, render product detail by SKU (reuse `ProductDetailWithPreview` + the `[...slug]` prefetch/JSON-LD/breadcrumb pattern) with canonical `/{lang}/{slug}` → else `notFound()`. Mirror `generateMetadata` similarly.
3. **Dynamic category root (D2/D3 multi-segment):** fetch `categoryRoot` from `seo-config`; use it for links/canonical/breadcrumb/sitemap. Add a `middleware.ts` rewrite: `/{lang}/{root}/{rest}` → `/{lang}/categorie/{rest}` when `root === categoryRoot[lang] && root !== 'categorie'`. Keep `/categorie` working (back-compat) with a 301 to the configured root when they differ.
4. **Canonical on SKU routes (D4):** in `products/page.tsx` + `products/[...slug]/page.tsx` `generateMetadata`, set canonical to `/{lang}/{slug}` when the product has a slug.
5. **`sitemap.ts`:** fetch vcs `sitemap-data`, map to `MetadataRoute.Sitemap`; fall back to current local generation on failure.
6. **`robots.ts`:** fetch vcs `seo-config.robots`; emit per-tenant rules (and `Disallow: /` when `noindex`); fall back to current static rules on failure.
7. **Tests:** `[slug]` disambiguation order (CMS→product→404, mock vcs), middleware rewrite, sitemap/robots mapping from mocked vcs payloads, canonical emission.

## 8. Testing strategy

Unit tests in each repo (vitest). Mock the vcs HTTP boundary in vinc-b2b. No live PIM calls in tests. Verify: slug filter forwarding, resolver shapes, disambiguation order, middleware rewrite, sitemap/robots mapping, canonical URLs.

## 9. Risks & rollout

- **Slug collisions / duplicate content:** canonical always points to one flat slug; `/products/{sku}` is non-canonical.
- **vcs availability:** every vinc-b2b consumer has a safe fallback to current behavior, so an vcs outage degrades to today's behavior, not a 500.
- **Category route refactor risk:** mitigated by keeping `/categorie/[[...slug]]` intact and layering the dynamic root via middleware rewrite (no rip-and-replace).
- **PIM slug filter support unknown:** resolver has a Mongo fallback (vcs owns the data) so the feature does not block on the search engine.

## 10. Open items / assumptions (override on review)

- **(b)** Category root is per-tenant **and** per-locale (`it: prodotti`, `en: products`); default `categorie`. If you want a single string across locales, drop the per-locale map.
- Disambiguation order is **CMS → product** (CMS wins) on single-segment collisions.
- Product slugs are single-segment (hyphenated); multi-segment slugs are not supported by the `[slug]` route (they'd need the catch-all).
